Metodologia

La detection è rule-based e combina più livelli di evidenza raccolti durante la pipeline. L'obiettivo non è indovinare la tecnologia da un solo indizio, ma accumulare marker coerenti per assegnare un framework primario, eventuali framework secondari, un CMS e un livello di confidenza.

Criteri Di Detection

  1. Marker nell'HTML La homepage salvata viene ispezionata per cercare firme note nel markup o nello stato iniziale della pagina. Esempi:

    • __NEXT_DATA__ o id="__next" per Next.js
    • __NUXT__ o id="__nuxt" per Nuxt
    • drupalSettings per Drupal
    • wp-content, wp-json o wordpress per WordPress
    • themeDisplay, Liferay.ThemeDisplay o Liferay.Loader per Liferay

  2. Marker negli URL degli asset Gli URL di script e fogli di stile vengono letti come segnali strutturali. Questo aiuta soprattutto per CMS e framework con percorsi standardizzati. Esempi:

    • wp-content, wp-includes, elementor, woocommerce per WordPress
    • /_next/ per Next.js
    • /_nuxt/ per Nuxt
    • /o/, __liferay__ o Liferay.Loader per Liferay

  3. Marker nel contenuto dei bundle JS Quando i bundle vengono scaricati, il detector cerca simboli e stringhe tipiche delle librerie realmente eseguite:

    • React, react.production, createElement
    • Vue, __VUE__, createApp(
    • @angular, zone.js
    • jQuery, $.fn.jquery
    • bootstrap, data-bs-toggle
    • bootstrap-italia, --bootstrap-italia-version
    • Liferay.Loader, Liferay.ThemeDisplay, Liferay.Portlet, @liferay/

  4. UI framework da CSS I CSS vengono usati soprattutto per intercettare framework di presentazione o builder:

    • Bootstrap
    • Bootstrap Italia
    • Tailwind CSS
    • Foundation
    • UIkit
    • Elementor

Come Viene Assegnato Il Risultato

  1. Framework primario Viene scelto il framework con più evidenze aggregate tra HTML, URL e contenuto dei bundle.

  2. Framework secondari Gli altri framework con marker presenti rimangono come secondari. Questo è utile nei siti ibridi, per esempio WordPress con widget React o pagine che caricano jQuery e Bootstrap.

    Quando compaiono marker specifici di Bootstrap Italia, il detector privilegia questa etichetta e non la fa ricadere automaticamente nel bucket generico Bootstrap.

  3. CMS primario Viene assegnato separatamente quando esistono marker forti di piattaforma editoriale.

  4. Confidenza

    • high quando il framework principale ha almeno tre evidenze
    • medium quando ha almeno una evidenza
    • low quando non ci sono segnali robusti o il risultato è debole
